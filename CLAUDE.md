# Coupon Finder — project guide for Claude

## Rule: keep this file updated

Whenever a change alters anything this file describes — commands, architecture, data model, API routes, scraper sources, verification logic, or user-facing features — update the relevant section of this CLAUDE.md **in the same change**. Stale guidance is worse than none.

## What this is

Local web app: search a company, get its active coupon/discount codes scraped from public aggregator sites. Personal/local use only.

## Commands

- `npm run install:all` — install root + server + client deps (first time only)
- `npm run dev` — start API (Express, :3001) and UI (Vite, http://localhost:5173) together via concurrently. Vite binds all interfaces (`host: true`) so LAN devices can use the app at `http://<machine-ip>:5173`; Express binds 127.0.0.1 only — LAN traffic reaches the API through Vite's `/api` proxy, never directly. Don't "fix" the API's bind address to 0.0.0.0. Phone access from anywhere runs over Tailscale (`allowedHosts: ['.ts.net']` in vite.config.js); the client is an installable PWA (`client/public/manifest.webmanifest` + icons generated by `client/scripts/make-icons.js`, iOS metas in index.html).
- `node server/test.js` — 24-test regression suite (grouping units, live API, live scrape/product/flyer sources); `--fast` skips the live-source tests. **Run it after any change to scrapers, routes, or grouping**; it needs the dev server running for the API section.
- Preview config for the Claude browser pane is in `.claude/launch.json` (name: `coupon-finder`)

## Architecture

- `server/` — Express API, ES modules, Node 22.
  - `index.js` — routes. **Do not read `process.env.PORT` here** — the preview harness sets it to Vite's port and the two servers collide (use `API_PORT`, default 3001).
  - `db.js` — better-sqlite3, schema + all queries. DB file: `server/coupons.db` (WAL).
  - `resolve.js` — company-name → domain via Clearbit's free autocomplete; `groupSuggestions()` merges near-duplicate brand entries (same normalized name OR same distinctive domain base label) **transitively via union-find** into one suggestion. Generic/short labels (`www`, `shop`, …) never merge. Representative pick: `.com` > logo > Clearbit order. Absorbed entries are kept in a `members` array so the UI can expand them — never discard them (distinct same-named companies must stay reachable).
  - `scrapers/` — one adapter per source, run in parallel via `Promise.allSettled` (a failing source is skipped, reported in `sourceErrors`; HTTP 404 = merchant not listed, filtered out, not an error). Slug-based adapters (`usesSlug = true`) are retried across `slugCandidates(domain, name)` (domain label, hyphenated name, joined name). Shared helpers live in `scrapers/util.js` (`toTs` date→epoch-or-null, `discountFrom` title→"25% off") — use them instead of re-rolling Date.parse guards. `index.js` merges, dedupes (code, else normalized title), demotes phrase-like "codes" ("Sign up for code") to deals, and assigns status.
  - `products.js` — product-level deal search via Slickdeals' public RSS search (`newsearch.php?rss=1&q=`); parses items with regex (title/link/description/pubDate), extracts price from title and coupon code from text (`extractCode` handles "coupon code XYZ" doubled keywords). In-memory 15-min cache.
- `client/` — Vite + React 18, plain CSS (`src/styles.css`, dark/light via `prefers-color-scheme`).
  - `App.jsx` (state + search flow), `SearchBar.jsx` (debounced autocomplete; the "▸ N more" chip expands merged variants into selectable rows; Enter only picks while the dropdown is open), `OfferCard.jsx` (status badge, freshness), `Sidebar.jsx` (history/favorites). Shared pieces: `useSearch.js` (fetch-state hook used by all three search surfaces), `CopyCode.jsx` (copy-to-clipboard chip), `util.js` (`timeAgo`).

## Scraper sources (checked 2026-11-21)

- **PromoCodes.com** — primary; full copyable codes + `isVerified`/`validatedDate`/`expirationDate` parsed from embedded `__NEXT_DATA__`. Slug: domain's first label (`nike.com` → `/nike`).
- **CouponFollow** — `couponfollow.com/site/<domain>` for the offer list (cheerio), then the site's own public modal endpoint reveals full codes: `GET couponfollow.com/api/v1/public/offer/modal/<domain>/<offerId>` with headers Chrome UA + `Accept: application/json` + `Referer: <merchant page URL>` (**Referer is mandatory** — the Fastly edge 403s without it). JSON response: `code` (plaintext), `isVerified`, `lastVerifiedOn`, `expiresOn`, `isExpired`, `discountInfo`. Bounded to 12 reveals/scrape, throttled 400ms. The teaser span in the HTML is the code's tail. `data-badge-type="official"` also counts as source-verified.
- **DealDrop** — SvelteKit data endpoint `dealdrop.com/<slug>/__data.json` exposes the full offer objects including the code strings that are click-to-reveal on their website, plus `verification_status`/`last_verified_at`. Objects map field names to indices in the node's flat `data` array. Do not hit `click.dealdrop.com`/`click.couponfollow.com` tracker URLs — that simulates affiliate clicks.
- **Coupons.com** — Next.js App Router; offers live in RSC flight chunks (`self.__next_f.push`). Reassemble chunk strings, brace-match each `"voucher":{...}` object: full `code`, `title`, `caption1/2`, `endTime` (expiry), `voucherStatistic.lastUsedDate` (freshness → verified if <7 days). Status 404 = merchant missing.
- **Savings.com** — server-rendered `div.module-deal` cards; the on-page code slot is empty, but each `hasCode` card's `input[name="property-popup-url"]` points to a static popup page whose `input.code` value is the full code (capped at 12 popup fetches). Expiry from per-offer ld+json `validThrough`. Page mixes in related merchants — filter by merchant-name ↔ domain-label match.
- **DontPayFull** — `dontpayfull.com/at/<domain>`: active cards (`div.card.obox.code`, not `.oexpired`/`.to-store`) mask codes as `***SUFFIX`, but the page's activity timeline (`.coupon-timeline-item--active` → `span.activity-code`) leaks the full codes; join by `code.endsWith(suffix)`. Unmatched timeline codes become standalone offers. Intermittently 403s (bot wall) — degrades gracefully.
- **DealHack** — `dealhack.com/coupons/<slug>` serves plainly; offers are inline minified JS object literals (`offerId:"...",title:"...",code:"..."` — not JSON, regex per `offerId:"` chunk). Rich health fields: `isVerified` (`!0`/`!1`), `lastWorkedAt` (→ verifiedAt), `expiresOn`. **The payload also embeds RELATED merchants' offers** — filter chunks by `dn=<domain>` in the monetization params (the string identifies the owning merchant; never request those URLs). Savings.com needs the same care: require a positive `.deal-merchant-name` ↔ domain-label match, cards without a merchant name are cross-store modules.
- **Off-limits — bot-walled by design**: RetailMeNot, Wethrift, SimplyCodes, Knoji, CouponBirds, Coupert, GoodShop, CouponCabin, CNN/USAToday coupons, CouponAnnie serve Cloudflare challenges to automated clients — including headless Chromium/Chrome (tested via Playwright on 2026-11-21; the dependency and helper were removed afterward as dead weight). Defeating their gates (header spoofing, challenge solving) is circumventing access controls — don't. Probed and rejected for other reasons: HotDeals (masks codes server-side), Brad's Deals (works but cross-lists other merchants' codes — conflation risk), CouponCause (unpredictable slugs, near-zero code yield), OffersDotCom/DealCatcher/CouponChief/DiscountReactor/Promocodie (blocked or JS-only).
- **Product deals**: Slickdeals RSS search works; DealNews RSS is gone (404) and Reddit JSON is bot-blocked (403).
- **Weekly flyers**: Flipp backend `backflipp.wishabi.com/flipp/items/search?locale=en-us&postal_code=<zip>&q=<query>` (what the Flipp app uses) — `items[]` carries name, merchant_name, current_price, valid_from/to, flyer images. `server/flyers.js`, 30-min in-memory cache, `/api/flyers?q=&postal=`. When the query matches no product items, the route falls back to a merchant-name match and returns that store's whole circular — ALL items (`merchant` and `total` set; the UI adds a client-side filter box). `/api/store-flyer` caps at 24 and reports `total`; the Store coupons section links users to the flyers tab for the rest.
- **Freshop grocers** (local chains Flipp doesn't carry, e.g. Donelan's near Acton MA): their sites run on Freshop (Instacart) with a public JSON API. `FRESHOP_GROCERS` in `server/flyers.js` maps normalized store names to `app_key` (found in the site's HTML, e.g. `app_key=donelans`). Flow: `/1/stores?app_key=` → walk candidate stores (chain-level first) until `/1/circulars?store_id=` has one → `/1/products?circular_id=&store_id=&limit=600` (API caps at 100 items, ignores offset — that's the ceiling). Prices: `offer_sale_price` (sale) vs `unit_price` (regular); images need the `_large` suffix: `images.freshop.ncrcloud.com/<cover_image>_large.png`. Add new grocers by finding their app_key the same way.
## Verification model ("Verified" / "Unconfirmed")

Codes cannot be test-applied at real checkouts (bot protection / needs a cart session; probed 2026-11-21 — Shopify cart endpoints are 404/403/429 on major stores, so a simulated-cart checker is not viable). `assignStatus()` in `server/scrapers/index.js` marks an offer **verified** when a source validated it within 60 days, the source flags it verified, or it's corroborated by 2+ sources; otherwise **unconfirmed**. Expired codes are dropped in the adapter. "⟳ Refresh & re-check" forces a re-scrape (`refresh=1`).

## Data model (SQLite)

- `companies(domain PK, name, logo_url, last_fetched_at)` — `last_fetched_at` drives the 6h cache TTL
- `offers(domain, dedupe_key UNIQUE per domain, code, title, …, status, verified_at, expires_at, kind, first_seen_at, last_seen_at)` — upsert bumps `last_seen_at` (freshness badge). `kind` ∈ `code`/`deal`/`hidden` (hidden = source has the code but didn't yield it; UI collapses these behind a "click-to-reveal on other sites" expander). After a successful re-scrape, `pruneStaleOffers` deletes rows the sources no longer list — old code-less twins of revealed codes go away with them.
- `history`, `favorites` — history display dedupes by company name (most recent domain wins)

## API

- `GET /api/suggest?q=` — grouped company suggestions
- `GET /api/search?domain=&name=&logo=[&refresh=1]` — cache-or-scrape; returns `{company, offers, cached, fetchedAt, sourceErrors}`. Offers are ranked by `rankOffers`: within each group (codes/deals/hidden) verified first, then discount size, then freshness; the client crowns the first verified code "★ Best pick".
- `GET /api/products?q=` — product deal search (Slickdeals RSS), returns `{deals, cached}`
- `GET /api/store-flyer?name=&postal=` — the searched store's current weekly flyer (best-effort: `{items:[]}` on any failure). Two-step Flipp call: merchant-name search returns flyer tiles (name:null, carry `flyer_id`), then `/flipp/flyers/<id>` returns the named item list.
- `GET /api/history`, `GET|POST|DELETE /api/favorites/:domain`

## UI modes

`App.jsx` has three tabs: **Store coupons** (company search → codes/deals; when a ZIP is saved, a "This week's flyer" section shows the store's own circular — grocers like Market Basket get flyer results even with zero codes), **Product deals** (`ProductSearch.jsx`: free-text product query → Slickdeals deal cards), and **Weekly flyers** (`FlyerSearch.jsx`: ZIP (persisted in localStorage) + product → current weekly-ad items from chains near that ZIP).

## Gotchas

- Scraper selectors break when sites change markup; adapters are independent — fix one without touching others. Saved sample pages aren't kept; re-fetch with a Chrome User-Agent to inspect.
- Clearbit suggest data is noisy (typo'd names like "addidas", regional TLD duplicates) — that's why `groupSuggestions()` exists; don't trust its first row blindly.
- `node --watch` auto-restarts the server on edits; Vite hot-reloads the client.
